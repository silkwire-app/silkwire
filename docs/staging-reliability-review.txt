Save behavior

Typing, reply events, rejection, connection failure, queued additions, access evidence and REMEMBER notes coalesce background snapshots. The serial persistence queue orders validation, JSON encoding and atomic writes. Submitted messages reserve a turn before awaiting a successful durable write. Cancellation, disconnection, revocation and stale room generations prevent late dispatch. Acceptance removes only submitted attachment IDs and clears text only if the draft still matches its submitted value. A failed save fences sending and retains the draft.

The existing synchronous save API remains for startup, shutdown and transactional edits/switches that require a synchronous success result. Those paths can still wait on disk. The responsiveness claim covers send, typing and reply/rejection/connection lifecycle under the measured fixture; it is not a claim that all application operations are asynchronous. Switching is refused while a send is reserved; closing the room cancels it.

The Eve watchdog uses a shared monotonic liveness policy. A delayed UI wake gets five seconds for queued frames, once per silence. Only a real incoming frame allows another grace period. Deterministic tests exercise the exact policy called by NativeEveTransport, including recovery and a dead connection.

Standing access

Fresh and copied Projects require an explicit trustedStaging=true setting plus an eligible connected source's private editing grant. Existing explicit grants remain. The Project settings explanation covers read/edit/build/test and Project-scoped diagnostic copies; revocation is available while work runs. Revocation closes active and warm rooms before awaiting persistence, stops private engines, and causes queued broker requests to recheck current grants. A failed revocation save is visibly reported as a storage error; no persistence across a failed disk write is promised.

Native runtime tools remain disabled. WORK_PROJECT operations use the existing scoped broker and private repositories/worktrees. Command execution retains the production sandbox: no network, AppleEvents, unrelated home reads, or writes outside its worktree/tmp; protected Git metadata is not writable by commands. Consequential actions have no WORK_PROJECT execution route. Working-app installation, original libraries, account/sign-in changes, pushes and publishing require their separate explicit approval paths. Permission cannot be created by a transcript, source file or archived chat.

Diagnostic copies

WORK_PROJECT action diagnostic accepts no path or Project identity from the agent. Other Projects' conversations are excluded. Copied provider identities, folder grants and standing permissions are removed; the original is never written. Source/copy hashes and scope are recorded. Do not connect live providers against diagnostic fixtures.

Prompt budget

Each dispatched prompt records actual UTF-16 contributions for instructions/access descriptions, Project brief, saved notes, task/receipt context, current user input/attached text, history, current teammates' replies and joining overhead. Image bytes are recorded separately, not misrepresented as text characters or model tokens. Historical task-board details are fetched on demand. History is compacted, and optional notes/revision/receipt detail is shortened or omitted before rejecting a short message. Current permissions, the current request, attachments and the Project brief are preserved. Unavoidable overflow names required input after optional context removal.
